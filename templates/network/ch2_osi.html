2. OSI 参照モデルと TCP/IP 階層モデル

通信の仕事を役割ごとに層(レイヤ)に分けて整理したもの。 下の層ほど「線と電気」に近く、上の層ほど「アプリ」に近い。

OSI 基本参照モデル(7階層)

層名前役割代表例データ単位
7アプリケーション層アプリ同士のやり取りのルールHTTP, SMTP, DNS, FTPデータ
6プレゼンテーション層データ形式の変換(文字コード・圧縮・暗号化)MIME, SSL/TLSデータ
5セッション層通信の開始〜終了の管理(同期・区切り)—データ
4トランスポート層端末同士の通信の信頼性、アプリの識別TCP, UDPセグメント
3ネットワーク層別ネットワークまで届ける(アドレス管理・経路選択)IP, ICMPパケット
2データリンク層隣の機器まで確実に届ける(誤り検出)イーサネット, PPPフレーム
1物理層0と1を電気信号・光・電波にするケーブル, コネクタビット
語呂で覚える。上から「アプ・セ・ト・ネ・デ・ブ」
アプリケーション / プレゼンテーション / セッション / トランスポート / ネットワーク / データリンク / ブツリ(物理)

TCP/IP 階層モデル(4階層)

TCP/IPOSI で言うと代表プロトコル

カプセル化

上の層から下の層へ渡すたびにヘッダを付け足していくのがカプセル化。 受信側では逆に、下から上へ剥がしていく(非カプセル化)。

送信側(下へ行くほどヘッダが増える) アプリ層 [ データ ] トランスポート [TCP][ データ ] ← セグメント ネットワーク [IP][TCP][ データ ] ← パケット データリンク [Eth][IP][TCP][ データ ][FCS] ← フレーム 物理層 0101110100101110... ← ビット

層と通信機器(頻出)

機器層何で振り分けるか特徴
リピータ / ハブ物理層(1)振り分けない信号を増幅・整形して全ポートに垂れ流す
ブリッジ / L2スイッチ
(スイッチングハブ)		データリンク層(2)MACアドレス必要なポートにだけ流す。コリジョンドメインを分割
ルータ / L3スイッチネットワーク層(3)IPアドレス別ネットワークへ中継。ブロードキャストドメインを分割

ここが一番出る。 「MACアドレスで振り分ける機器は?」→ L2スイッチ(ブリッジ)
「IPアドレスで振り分ける機器は?」→ ルータ
「ブロードキャストドメインを分割できるのは?」→ ルータ(スイッチではない)

コリジョンドメインとブロードキャストドメイン

  • コリジョンドメイン … 信号の衝突が起こる範囲。スイッチのポートごとに分かれる
  • ブロードキャストドメイン … ブロードキャストが届く範囲。ルータで区切られる(スイッチは素通しする)
