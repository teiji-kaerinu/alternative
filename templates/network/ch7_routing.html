7-1. ルーティング(経路制御)

ルータの仕事は「宛先IPアドレスを見て、次にどこへ渡すかを決める」こと。 その判断表がルーティングテーブル。

宛先ネットワーク次に渡す相手(ネクストホップ)
192.168.1.0/24直接接続
192.168.2.0/2410.0.0.2
0.0.0.0/010.0.0.1(デフォルトルート)
  • デフォルトゲートウェイ … 自分のネットワークの外へ出るときの出口。「宛先が分からなければここへ」
  • デフォルトルート(0.0.0.0/0) … どの経路にも当てはまらないパケットの行き先
  • ロンゲストマッチ … 複数の経路が該当する場合、より長い(細かい)プレフィックスを優先する。 /24 と /16 が両方当てはまるなら /24 を選ぶ

静的ルーティングと動的ルーティング

静的ルーティング動的ルーティング
設定管理者が手で書くルータ同士が情報交換して自動で作る
長所負荷が軽い、動きが予測できる障害時に自動で迂回できる、規模が大きくても管理できる
短所構成が変わるたび手直し、障害時に迂回できない設定が複雑、やり取りの負荷がかかる

ルーティングプロトコル

名前種別方式特徴
RIPIGP(組織内)距離ベクトル型ホップ数(経由ルータ数)が少ない経路を選ぶ。 最大15ホップ、16で到達不能。小規模向け
OSPFIGP(組織内)リンクステート型コスト(帯域幅など)で最適経路を選ぶ。 エリア分割ができ大規模向け。収束が速い
BGPEGP(組織間)パスベクトル型AS(自律システム)同士を繋ぐ。 インターネットの基幹で使われる
RIP と OSPF の対比が頻出。 「ホップ数で選ぶ = RIP」「コストで選ぶ・大規模向け = OSPF」「AS間 = BGP」。 AS とは、同じ運用方針で管理されるネットワークのまとまり(ISP1社など)。

7-2. NAT(Network Address Translation)

プライベートIPアドレスとグローバルIPアドレスを1対1で相互変換する仕組み。 変換するのはIPアドレスだけ。

なぜ必要か

  • 家や社内のLANでは、自由に使えるプライベートIPアドレスを使っている
  • でもプライベートIPはインターネットにそのままでは出られない(途中のルータが捨てる)
  • そこで出口のルータが、外に出るときだけグローバルIPに着せ替えてやる = これがNAT
行き) PC 192.168.1.10 ──▶ [ルータ] ──▶ Web 93.184.216.34 送信元IPを書き換え: 192.168.1.10 → 203.0.113.5 帰り) Web 93.184.216.34 ──▶ [ルータ] ──▶ PC 192.168.1.10 宛先IPを書き換え: 203.0.113.5 → 192.168.1.10

ルータは「どの内部IPをどの外部IPに変換したか」を変換表(NATテーブル)に記録しておき、 戻ってきたパケットを元の相手に返す。

内部IP外部IP
192.168.1.10203.0.113.5
192.168.1.11203.0.113.6 ← もう1個必要

弱点

アドレスしか覚えられないので、同時に外に出られるのはグローバルIPの数だけ。 10台同時に繋ぎたければグローバルIPが10個いる。これでは全然アドレスの節約にならない。 → そこで登場するのが NAPT。

7-3. NAPT(Network Address Port Translation)

IPアドレスとポート番号をセットで変換する仕組み。 グローバルIPが1個だけでも複数台が同時にインターネットに出られる。

別名に注意。試験ではこれ全部おなじものとして出ます。
NAPT = IPマスカレード(Linux) = PAT(Cisco) = NATオーバーロード

変換表にポート番号が入る

2台が同時に同じサイト(93.184.216.34:80)を見た場合:

内部 IP:ポート外部 IP:ポート宛先
192.168.1.10:50001203.0.113.5:6000193.184.216.34:80
192.168.1.11:50001203.0.113.5:6000293.184.216.34:80

外から見ると2台とも同じ 203.0.113.5 だが、ポート番号が違う。 返ってきたパケットの宛先ポートが60001なら1台目、60002なら2台目 ── と一意に振り分けられる。

ポート番号は16ビット = 65536通りあるので、理論上はグローバルIP1個で数万セッションを まかなえる。これが「NAPTはIPv4アドレス枯渇の延命策」と言われる理由。

外から中への通信は原則できない

変換表にエントリが無い状態で外から 203.0.113.5:80 宛てに来ても、 ルータはどのPCに渡せばいいか分からず捨てる。 中でサーバを公開したいときはポートフォワーディング(静的NAPT)で 「80番宛ては 192.168.1.20 へ」と手で登録しておく必要がある。

結果として外部からの不正アクセスが届きにくいという副次効果はあるが、 ファイアウォールの代わりにはならない。

NAPTの弱点(応用問題で狙われる)

  • ポート番号を持たないプロトコル … ICMPにはポートが無い。そこでEchoの Identifierフィールドをポート番号の代わりに使って識別する
  • ペイロードにIPアドレスを埋め込むプロトコル … FTPのアクティブモード(PORTコマンド)やSIP。 ヘッダだけ直しても中身にプライベートIPが残るので壊れる → ALG(Application Level Gateway)で中身まで書き換える必要がある
  • IPsecのAHが通らない … AHはIPヘッダごと認証するため、書き換え = 改ざん扱いになる。 ESPはNAT-T(UDP4500でカプセル化)で回避する
  • エンドツーエンド性の喪失 … P2P・オンラインゲーム・VoIPが繋がりにくい。 STUN / TURN / UPnP といった穴あけ技術が要る

覚え方。NAT に P が増えた = Port が増えた。
「NAT = アドレスだけ」「NAPT = アドレス + ポート」。ここさえ押さえれば大体解ける。

よく出る問題パターン

  • 「1個のグローバルIPで複数台が同時に接続できるのはどれか」→ NAPT
  • 「NAPTが変換するものを2つ答えよ」→ IPアドレスとポート番号
  • 「IPマスカレードと同じものはどれか」→ NAPT
  • 「NAPTで、ポート番号を持たないICMPをどう識別するか」→ Identifierフィールドを使う
おまけ:NPTv6。IPv6にはNPTv6(RFC 6296)という別物がある。 これはIPアドレスの上位プレフィックスだけを1:1でステートレスに変換するもので、 ポート番号には触らない。目的もアドレス節約ではなく「ISPを変えても社内アドレスを変えなくて済む」こと。 FEの範囲外だが、NAPTと混同しないよう注意。
