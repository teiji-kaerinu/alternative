6. 主要なプロトコル

DNS(Domain Name System)

ドメイン名とIPアドレスを対応づける仕組み。 人間は www.example.co.jp を覚え、機械は 93.184.216.34 を使うので、その翻訳役。

  • 正引き … ドメイン名 → IPアドレス(普通はこっち)
  • 逆引き … IPアドレス → ドメイン名
  • 世界中のDNSサーバが階層構造で分担している(ルート → jp → co.jp → example.co.jp)
  • キャッシュサーバが一度調べた結果を保存し、次から高速に答える
  • ポートは 53。通常の問い合わせは UDP、ゾーン転送は TCP
レコード内容
Aドメイン名 → IPv4アドレス
AAAAドメイン名 → IPv6アドレス
MXメールサーバの指定
CNAME別名(エイリアス)
NSそのドメインを管理するDNSサーバ
PTR逆引き用

DHCP(Dynamic Host Configuration Protocol)

IPアドレスなどの設定を自動で配る仕組み。 配るのは IPアドレス・サブネットマスク・デフォルトゲートウェイ・DNSサーバのアドレス。

クライアント DHCPサーバ │── ① DISCOVER(ブロードキャスト)─▶│ 「誰かIPくれ」 │◀─ ② OFFER ───────────────────│ 「これ使う?」 │── ③ REQUEST ─────────────────▶│ 「それください」 │◀─ ④ ACK ─────────────────────│ 「どうぞ」
  • 頭文字で D → O → R → A(ドーラ)と覚える
  • 配られたアドレスにはリース期間(貸出期限)がある。期限が切れる前に更新する
  • DHCPサーバが見つからないと 169.254.x.x(APIPA)が自動で付く

ARP(Address Resolution Protocol)

IPアドレスから MACアドレスを調べるプロトコル。 実際にフレームを送るには MACアドレスが必要なので、送信直前に必ず使われる。

① 「192.168.1.1 の人、MACアドレス教えて!」 → ブロードキャストで全員に聞く(ARPリクエスト) ② 「それ私です。00-1B-44-11-3A-B7 です」 → 本人だけがユニキャストで返す(ARPリプライ) ③ 結果は ARPテーブル(キャッシュ)に一定時間保存する

RARP は逆に MACアドレスから IPアドレスを調べる(ディスクレス端末などで使用)。

ICMP(Internet Control Message Protocol)

ネットワーク層のエラー通知・状態確認用。データを運ぶためのものではない。

  • ping … Echo Request / Echo Reply で疎通確認する。「相手は生きてるか」
  • traceroute(tracert) … TTLを1ずつ増やして送り、途中のルータを順番に洗い出す
  • TTL(Time To Live) … パケットの寿命。ルータを通るたびに1減り、0になると破棄される。 ループしたパケットが永久に回り続けるのを防ぐ

HTTP / HTTPS

  • Webページをやり取りするプロトコル。リクエストとレスポンスの繰り返し
  • ステートレス … 前回のやり取りを覚えていない。だから Cookie で状態を保持する
  • HTTPS は HTTP を SSL/TLS で暗号化したもの。ポート443

GETデータを取得する(URLに情報が乗る)
POSTデータを送信する(本文に情報が乗る)
PUT / DELETE更新 / 削除
コード意味

番号の頭で判断できる。 2xx = 成功 / 3xx = リダイレクト / 4xx = クライアント側が悪い / 5xx = サーバ側が悪い

メール関連

プロトコル役割ポート
SMTP送信とサーバ間の転送25(送信用に587も)
POP3受信。メールを端末にダウンロードして削除するのが基本110
IMAP4受信。メールをサーバに置いたまま管理する。複数端末で見るのに向く143
送信者 ──SMTP──▶ 送信メールサーバ ──SMTP──▶ 受信メールサーバ │ POP3/IMAP4 で取りに行く ▼ 受信者
  • MIME … 本来ASCIIしか運べないメールで、日本語や画像・添付ファイルを扱えるようにする拡張。 暗号化・署名まで対応したものが S/MIME
  • SMTP-AUTH … メール送信時にユーザ認証を行い、迷惑メールの踏み台にされるのを防ぐ
  • OP25B(Outbound Port 25 Blocking) … ISPが外向きのポート25を遮断し、迷惑メールを抑止する仕組み
  • SPF / DKIM / DMARC … 送信元のなりすましを検出する仕組み
