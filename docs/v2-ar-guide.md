# v2 設計メモ：作画ガイドとAR合成

> **AIが測って、人間が描く。**
> 巡礼地の写真をAIが解析して「描くための指示書（作画ガイド）」を出し、それに合わせて自分が完成絵を描く。
> 合成のときにAIがやるのは、色・影・ぼけ・ノイズをなじませることだけ。絵そのものは描き換えない。

- 状態：構想（実装は MVP〈F1〜F6〉と佐渡巡礼〈2026/12/25〜27〉が終わってから）
- 方針を決めた日：2026-10-21

---

## 1. なぜやるか

- マブラヴの聖地は、作中の背景と同じ構図で撮れる場所が少ない。「構図を合わせる」より「その場所に自分のキャラを立たせる」方が、この作品の巡礼に合っている。
- 自分は絵を描ける。写真に合わせて描けるのは絵描きだけなので、他の人には真似できない。
- 画像処理・機械学習・Webを、1つの機能でまとめて見せられる。

---

## 2. 使う流れ

### 2-1. 現地で撮る（開発しなくてもできる。ここで素材の質が決まる）

| 撮るもの・撮り方 | 理由 |
|---|---|
| 目の高さで、スマホを上下に傾けずに撮る | 地平線＝目の高さになり、キャラの大きさを計算できる（5-1）。立ち絵とも視点が合う |
| 同じ構図で「誰もいない版」と「人が立っている版」を撮る | 人あり版が、大きさ・影の向き・光の色を確かめる基準になる |
| キャラを立たせたい場所の足元が写るようにする | 地面との接点が見えないと浮いて見える |
| 白い紙（スケッチブック）を、現地の光で1枚撮る | 光の色の基準になる |
| 影の向きが分かるカットを撮る | 光の向きの確認に使う |
| 位置情報をオンのまま撮る | 撮影時刻と位置から、太陽の向きと高さを計算できる（5-3） |
| できれば曇りの日に撮る | 影が柔らかいので合成しやすい |

### 2-2. 帰ってから：作画ガイドを作る

1. 訪問記録（F3）に「誰もいない版」の写真を投稿する。
2. 訪問記録の「作画ガイドを作る」ボタンを押す。
3. ガイド画面で、写真の上に次の3つを指定する（最初は手で入力し、あとで自動化する）。
   - **地平線**：横線を上下にドラッグする。写真が傾いていたら角度も合わせる。
   - **足元**：キャラを立たせたい地面の点をクリックする。
   - **光の向き**：矢印をドラッグする（自動で出せる場合は初期値が入っている）。
4. 入力すると、すぐに次が計算されて写真の上に重ねて表示される。
   - キャラのガイド枠（身長に合わせた縦の長さと、目の高さの線）
   - 遠近の線（消失点に向かう線）
   - 影の向きと長さの目安
5. 横の数値パネルに、測った値が並ぶ。
   - 光の色（色温度）、影の濃さと柔らかさ、背景のぼけ、写真のノイズ、ガイド枠の大きさ（px）
6. 「下描き用ガイドPNGをダウンロード」で、写真にガイド線を重ねた画像を、写真と同じ解像度で保存する。

### 2-3. 描く（アプリの外、作画ソフトで）

- ガイドPNGを一番下のレイヤーに敷いて、ガイド枠の中にキャラを描く。
- 光の向き・光の色・影の濃さは、数値パネルを見ながら塗りに反映する。
- 書き出すときは、**キャンバスを写真と同じ解像度・同じ位置のまま**、キャラのレイヤーだけを透過PNGにする。こうすると、合成のときに位置合わせがほぼ要らなくなる。
- 手前に来る物（柵など）は、写真をなぞって「遮蔽マスク」のレイヤーを作り、それも書き出しておく（自動化する前の手動版。5-8）。

### 2-4. 合成する

1. 訪問記録の「合成」画面で、完成絵（透過PNG）をアップロードする。
2. 写真と同じサイズなら、そのままぴったり重なる。サイズが違うときは、ガイド枠に合わせて自動で置き、ドラッグで微調整する。
3. 「なじませ」パネルで仕上げる。各スライダーには、測った値が初期値として入っている。
   - 色合わせの強さ、影の濃さと柔らかさ、ぼけ、ノイズ、輪郭のなじみ（ライトラップ）
4. プレビューでは、合成前と合成後を左右にスライドして見比べる。
5. 保存すると、完成画像を Cloudinary に保存し、訪問記録の「シーン」として表示する。

### 2-5. 見せる

- スポット詳細：訪問記録に「シーン」を表示し、元の写真・完成絵・合成結果を切り替えて見られる。
- ギャラリー：「巡礼 × イラスト」の一覧。
- 公開する前に、写り込んだ他人の顔はぼかす。

## 5. 測り方

それぞれ「手動版」で先に作り、あとから「自動版」に置き換える。

### 5-1. キャラの大きさ（機械学習なしで計算できる）

目の高さで、スマホを上下に傾けずに撮った写真では、次の関係が成り立つ。

**キャラの高さ(px) ＝（足元のy − 地平線のy）×（キャラの身長 ÷ カメラの高さ）**

- 例：地平線が y=800、足元が y=1400、カメラの高さ 150cm、キャラの身長 160cm なら、(1400 − 800) × 160 ÷ 150 ＝ 640px。
- 立っている人の目の高さは、どの距離にいても地平線とほぼ同じ高さに来る（カメラの高さと目の高さが同じなら）。ガイド枠に「目の高さの線」を引くのはこのため。
- 確かめ方：人あり版の写真で、実際の人の身長(px)と計算値を比べる。
- 使う知識：遠近法（ピンホールカメラの考え方）。機械学習は使わない。

### 5-2. 地平線と遠近の線

- 手動版：横線をドラッグする。
- 自動版：輪郭フィルタ（ソーベル＝畳み込み）で線を拾い、直線検出（ハフ変換）で平行な線の組を集める。それらの交点が消失点で、消失点を通る水平線が地平線になる。スマホの左右の傾きも、線の角度から補正する。
- 海が写っていれば、水平線そのものが地平線になる。

### 5-3. 光の向きと影の長さ

- 手動版：影の向きを見て、矢印をドラッグする。
- 自動版1（機械学習なし）：撮影時刻と位置（写真のEXIF）から、天文計算のライブラリで太陽の方位と高さを出す。iPhone など撮影方向も記録する機種なら、画面のどちら側から光が来るかまで計算できる。
  - 影の長さ ＝ 身長 ÷ tan(太陽の高さ)。12月末の佐渡（北緯約38度）だと、正午でも太陽の高さは30度弱で、影は身長の約1.8倍になる。
- 自動版2：人あり版の写真で、人の影の向きを測る（人物の切り抜き＋影の検出）。
- 曇りの日は、太陽の向きよりも「空全体からの柔らかい光」として扱う（影は薄く、柔らかく、真下寄り）。

### 5-4. 光の色（色温度）

- 基準カット：白い紙の写真の色の比率から、光の色を出す（一番確実）。
- 自動版1（機械学習なし）：「写真全体の色を平均すると、だいたい灰色になる」という仮定（グレーワールド）で、光の色を推定する。
- 自動版2（機械学習）：色恒常性推定のCNN（写真のどこが本来は白いはずかを学習したモデル）を使う。

### 5-5. 影の濃さと柔らかさ

- 人あり版の写真で、人の影の中と外の地面の明るさの比から、影の濃さを出す。
- 影の輪郭のぼけ具合（輪郭フィルタの反応の強さ）から、柔らかさを出す。
- 手動版：天気（晴れ／薄曇り／曇り）を選ぶと、初期値が入る。

### 5-6. 背景のぼけ

- 足元の周りの背景にラプラシアンフィルタ（畳み込み）をかけ、値のばらつきから「どれくらいくっきりしているか」を測る。
- キャラにも、同じくっきり具合になるまでぼかしをかける。

### 5-7. 写真のノイズ

- 空などの平らな所で、画素の細かいばらつきを測る。
- 同じ強さの細かいノイズを、キャラにも足す。
- 写真のノイズは細かいザラつき（ガウス状）で、卒研で扱った salt & pepper とは種類が違う。

### 5-8. 前後関係（手前の物）

- 手動版：作画ソフトで写真をなぞって、遮蔽マスクを描く（絵描きなら一番早い）。
- 自動版1：深度推定モデル（Depth Anything V2 など）で奥行きの地図を作り、足元より手前にある画素をマスクの候補にする。
- 自動版2：物の切り抜きモデル（Segment Anything 系）で、柵などをクリックするとその形のマスクができるようにする。
- 深度推定の値は「相対的な近さ」で、メートルではない。だから大きさは 5-1 の幾何で出し、深度は前後関係だけに使う。

## 6. 合成の手順（なじませの中身）

下から順に重ねる。

1. **背景**：元の写真。
2. **影**：キャラの透明度（アルファ）から影の形を作る → 光の向きに合わせて地面に倒す（横にずらし、縦につぶす）→ 柔らかさに合わせてぼかす → 地面に乗算で重ねる。
3. **接地影**：足元に、小さくて濃い影を足す。これがないと浮いて見える。
4. **キャラ**
   - 色合わせ：まず光の色に合わせて色味を寄せ、次に足元の周りの背景の明るさとコントラストに寄せる（平均とばらつきをそろえる。BatchNormと同じ考え方）。絵の色を壊さないよう、強さはスライダーで弱めにする。
   - ぼけ：5-6 で測った量だけぼかす。
   - 輪郭のなじみ：背景の明るさを、キャラの輪郭に少しだけにじませる（ライトラップ）。
5. **手前の物**：遮蔽マスクの部分だけ、元の写真を一番上に戻す。
6. **ノイズ**：5-7 で測った量のノイズをキャラの部分に足して、写真と質感をそろえる。

## 7. どこで動かすか

| 処理 | 動かす場所 | 理由 |
|---|---|---|
| 画面、データ、手動入力 | 本番（Flask＋Render） | MVPと同じ |
| ガイド線の描画、大きさの計算、太陽の計算、グレーワールド、ぼけとノイズの測定 | 本番 | NumPy と Pillow だけで済み、軽い |
| 合成（なじませ） | 本番 | 同上。画像1枚なら数秒で終わるはず（要計測） |
| 深度推定、物の切り抜き、色恒常性CNN | 手元のPC | PyTorch が重く、無料枠のサーバーには載らない |

- 手元PCの処理は、管理用のコマンドにする。「解析待ち」の Guide をまとめて取ってきて、奥行きの地図やマスクを作って Cloudinary にアップし、Guide を「解析済み」に更新する。
- 将来、本番でも動かしたくなったら、小さいモデルを ONNX Runtime（または自作の NumPy 推論）で載せる。

## 8. 段階（それぞれの完成の定義）

| 段階 | やること | 完成の定義 |
|---|---|---|
| v2-0 | 佐渡で撮影する（2-1 のルールで） | 立たせたい場所ごとに「無人版・人あり版・足元・白い紙」がそろっている |
| v2-1 | 作画ガイド（手動入力版）：地平線・足元・光の矢印の入力、大きさの計算、ガイドPNGの出力 | ガイドPNGを敷いて、実際に1枚描ける |
| v2-2 | 合成（手動の値で）：アップロード、配置、影、色合わせ、ぼけ、ノイズ、前後比較 | 佐渡の写真1枚で「浮いていない」合成が1枚できる |
| v2-3 | 自動化（機械学習なし）：EXIFからの太陽計算、グレーワールド、ぼけとノイズの自動測定、直線検出による地平線 | 手動入力が「確認するだけ」で済む |
| v2-4 | 自動化（機械学習）：深度推定と切り抜きで前後関係。余力があれば色恒常性CNN | 柵の後ろに立つ合成が、マスクを手で描かずにできる |

**v2-1 と v2-2 だけで、「AIが測って、人間が描く」の流れは一周する。** まずここまでを完成させ、自動化は1つずつ足す。

## 9. 確かめ方

- **大きさ**：人あり版の写真で、実際の人の身長(px)と計算値の差（％）を記録する。
- **光の色**：白い紙の基準カットから出した色温度と、自動推定の差を記録する。
- **見た目**：合成した写真と本物の写真を混ぜて人に見せ、「どれが合成か」を当ててもらう。当てられなければ成功。
- **処理時間**：本番で、合成1枚にかかる時間を測る。

## 10. 気をつけること

| リスク | 対策 |
|---|---|
| 晴れの日の強い影は合わせにくい | 曇りの日を選ぶ。影の形は絵の側で描き足す |
| 深度推定の値はメートルではない | 大きさは幾何（5-1）で出し、深度は前後関係だけに使う |
| スマホが撮影方向を記録していない | 光の向きは手動の矢印で入れる |
| スマホを上下に傾けて撮ってしまった | 5-1 の式がずれる。撮影ルールで防ぎ、ずれは人あり版で確認する |
| 写真に他人が写っている | 公開する前に顔をぼかす |
| マブラヴの二次創作を公開する | 権利元のガイドラインを確認してから載せる |
| 機能が膨らんで終わらない | v2-1・v2-2 で1枚完成させるまで、自動化には手を出さない |
| 生成AIで絵が描き換わってしまう | 使わない。使うとしても、光の当たり方の参考を見るだけにする |

## 11. 面接で話せること

- 手動で動く版を先に作り、測る工程を1つずつ自動化した。
- 機械学習を使う所と使わない所を分けた（大きさ＝幾何、光の向き＝天文計算、前後関係＝深度推定）。
- 重い処理を本番から切り離した（手元PCの解析コマンドと、状態の管理）。
- 絵はAIに描かせず、AIは現場を測る道具として使った。
