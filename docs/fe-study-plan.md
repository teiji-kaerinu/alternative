## 科目Bの鉄則（自分の失点から）

### 0. 手を動かす前に、問題の型を見分ける

これが最上位。型を間違えると手順ごと無駄になる。

| 型 | 見分け方 | 取る手 |
|---|---|---|
| **トレース型** | ループ・分岐・変数の書き換えがある | 紙に変数の表。選択肢は先に見ない |
| **翻訳型** | `return` 1行の穴埋め。選択肢が式の羅列 | 式を書き換えるだけ。具体値で選択肢を潰す |
| **読解型** | 情報セキュリティの4問。シナリオ＋条件の長文 | **設問を先に読む。**探すものを決めてから本文に入る |

### 1. 翻訳型：式を「変形」しない

問題文が「◯◯を返す」と言い切っている時点で、返す式は確定している。
**変形する余地はゼロ。** やるのは「同じ式を、使える道具だけで書き直す」こと。
変形を始めたら、存在しない問題を解いている。

- `√a` → `a の 0.5乗` → `pow(a, 0.5)`
- **外側から確定させる。** 一番外の演算を先に決めると選択肢が一気に絞れる
- 内側から組み立てると迷う

### 2. 翻訳型：具体値を入れて選択肢を潰す

`x=3, y=4` なら `√(x²+y²)=5`。選択肢に叩き込めば1組の数字で6個消える。
知識を思い出せなくても、これだけで取れる。

### 3. トレース型：難しく見える問題ほどトレースに戻る

簡単な問題は頭でも解けるが、難しい問題でトレースをやめると必ず落ちる。
人間は逆をやる。「これは頭を使う問題だ」と判断して、いちばん手が必要な場面で手を止める。

### 3.5 「解けない」の正体を切り分ける

科目Bで詰まったとき、原因は3つに分かれる。混ぜると対策を間違える。

| 詰まり方 | 正体 | 対策 |
|---|---|---|
| 手順を選び違えた | 型の判定ミス | 鉄則0に戻る（2026-09-12 問5） |
| 追えない・混乱する | トレース力不足 | 紙に書く量を増やす |
| **そもそも数が読めない** | **科目Aの基礎知識の穴** | **科目Aで埋める。粘っても出てこない**（2026-09-13 問16／16進数） |

3つ目が曲者で、科目Bの問題に見えて実体は科目Aの穴。
基数変換・ビット演算・計算量などが出てきて手が止まったら、それは知識不足であって
アルゴリズム力の問題ではない。**その場で粘らず、科目A側に回して後で戻る。**

### 4. 配列は 1始まり

Pythonの0始まりの癖で数えない。

科目Aを詰めれば科目Bも伸びる。二重取りが効く唯一の場所。

### 科目Bのセキュリティは、科目Aより知識依存度が低い

問20は EDR という未知の用語が選択肢にあったまま正解できた。問われているのが
知識そのものではなく、**設問と本文の対応を取る力**だから。解き方を型として残す。

1. 知らない用語が出ても **そこで止まらない**
2. **設問が何を聞いているかに戻る**（例：指摘1＝「職務が適切に分離されていない」）
3. **指摘に対する答えになっているか**で選択肢を切る
4. 「監視を足しても分離はされない」——別の軸の強化は、指摘への答えにならない

**知らないカタカナ用語は、もっともらしいダミーとして置かれていることが多い。**
「分からない＝高度な対策＝正解では？」と考えると落ちる。根拠のある方を選ぶ。

→ 結論：**4問全取りは射程内に見える**（ただし母数4問。断定はしない）。
