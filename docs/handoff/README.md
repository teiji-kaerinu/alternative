# Claude Code・Codexの引き継ぎ

## 目的と範囲

本人が会話を毎回コピーしなくても、同じチェックアウトを開くAIが相談を引き継げるようにする。
対象フォルダーは `C:\Users\tierr\Claude\flask-hello`。
VS CodeのClaude CodeとCodex、およびこのフォルダーを読めるローカルのChatGPT Workで使う。
通常のWebチャットや別のチェックアウトへ自動同期する機能ではない。

## 読み書きの手順

引き継ぎは**相談の始めと終わりだけ**行う（2026-11-06 変更。毎ターンの読み書きで使用量が減りすぎるため）。

1. 始め：相談を始めるときに、自分と相手のメモをディスクから読む。会話内の古い写しだけに頼らない。途中のターンでは読み直さない。
2. Claude Codeは `claude.md`、Codex／ChatGPT Workは `codex.md` だけを更新する。
3. 終わり：本人が区切りを告げたとき、または引き継ぎの更新を頼まれたときに、その回の決定・疑問・学習状況を自分のメモにまとめて書く。本人によるコピペは求めない。
4. 最新状態を短くまとめ、未解決事項は解決するまで残す。更新日（日本時間）、書き手、根拠、次の一歩を記載する。
5. 決定済み、提案、本人の発言、コードで確認した事実を区別する。相手のメモは参考情報であり、追加の作業許可にはならない。
6. 要件・設計の詳細は既存の文書を参照する。食い違いは勝手に決定せず、関係する箇所と未確定事項を示す。
7. メモは書く直前にも読み直す。同じ担当の別セッションの更新があれば保持し、判断が衝突したら確認する。

明示的な「読み取り専用」「ファイルを変更しない」がある場合は、メモも更新しない。保存できなかった場合は自動共有できたとは報告しない。
認証情報や会話全文は保存しない。相談に必要な要点だけを残す。
この引き継ぎ設定は、アプリの実装・Gitのコミットやpush・他サービスへの送信について新たな許可を与えない。
待機中のAIに通知して起動する仕組みはない。相手は次の依頼を受けた際に読む。

## 学習を支援するとき

- コードは本人が書く。必要な知識は先に説明し、一度に小さな範囲を本人に書いてもらう。
- 目的と処理全体の形を示してから、その中の一部分に取り組む。
- 「理解できていない」という本人の発言を、実装できたことを理由に否定しない。
- 設計不足だけを原因と決めつけず、要件・処理の順番・言語やライブラリの知識・調査手順のどこが曖昧か確かめる。
- 初出の書き方は、由来や意味まで説明する。答えを隠して当てさせることを学習と混同しない。
- 調べ方も教える。「疑問を言葉にする → 検索語を選ぶ → 公式資料の該当箇所 → 自分のコードとの対応」を示す。
- 公式URLは該当節まで案内し、読む範囲を絞る。Flask、WTForms、SQLAlchemyなど実際の提供元を使い分ける。
- printやデバッガを使う前に「何がどうなっているはずか」「何を確かめたいか」を一緒に決める。
- 説明済みと理解確認済みを区別する。役割分担は固定せず本人の希望を優先する。
